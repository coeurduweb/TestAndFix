# Translation (i18n)

Six languages, the six most used content languages of the web according to W3Techs (12 November 2026):
English (default), Spanish, German, Japanese, French, Portuguese.

## How it works

- **The French sentence is the key** (gettext style). Code is written in French and wrapped:
  `t('Mesurer à nouveau')`. Each other language has a catalog `i18n/<side>.<lang>.json`
  (`side` = `web` or `server`) mapping the French sentence to its translation. A missing
  translation falls back to English, then to French: a message is never empty.
- **Language of the visitor** (web, `web/src/lib/i18n.tsx`): their choice (localStorage), else the
  first browser language supported, else English. It is written to the `lang` cookie.
- **Language of the server** (`server/src/i18n.ts`): the `lang` cookie, else `Accept-Language`, else
  English, bound to each request with AsyncLocalStorage. A message received by SMTP is analysed in
  the language stored with its test address (`mail_addresses.lang`).
- **Knowledge base**: `knowledge/situations/*.yaml` stays the French source; translations live in
  `knowledge/i18n/<lang>/<same file name>.yaml`, keyed by situation id, with `title`, `why`, `fix`
  (same number of items) and `fix_by_provider`. `knowledge()` returns the base in the current language.
- Results are written in the language of the measurement and stored as such: a report measured in
  English stays in English in the history.

## Rules for the code

| Do | Example |
|---|---|
| Wrap every text a person reads: JSX text, `aria-label`, `title`, `placeholder`, `alt`, toasts, error messages, labels held in data, findings, verdicts, `pass()` titles, fallbacks | `<button>{t('Copier le lien')}</button>` |
| One whole sentence per message, values as `{placeholders}`; never glue translated pieces together | `t('Mesuré le {date}', { date })`, not `t('Mesuré le') + ' ' + date` |
| Counts: `plural(n, 'jour', 'jours')` for "3 jours"; `tn(n, '{n} jour restant', '{n} jours restants')` for a sentence | the language picks the form (Intl.PluralRules) |
| Markup inside a sentence: `rich()` with tags (no nesting) | `rich('Expire le <b>{date}</b>', { date }, { b: (c) => <strong>{c}</strong> })` |
| Text defined at module level (constants, tables, tool metadata): mark it with `msg()` and call `t()` where it is shown | `const LABEL = { ok: msg('conforme') }` then `t(LABEL.ok)` |
| Dates and numbers through the helpers (`fmtDateTime`, `fmtInt`, `locale()`) | never `'fr-FR'` in the code |

Never call `t()` at module level: modules are evaluated before the language is known (web) or
outside any request (server), so the text would freeze in the default language.

Not translated: CSS classes, ids, keys, routes, URLs, DNS record syntax (`v=spf1`, `p=reject`),
protocol and RFC names, EPP status codes, SpamAssassin rule names, log lines, comments, tests.

Keep the French wording as it is (it is the key and validated copy); only rebuild a sentence that
was split in pieces into one message with placeholders.

## Commands

```sh
node scripts/i18n.mjs extract   # msgids of the code -> i18n/{web,server}.msgids.json
node scripts/i18n.mjs todo      # what each language lacks -> i18n/todo/*.json (to fill)
node scripts/i18n.mjs merge     # filled todo files -> catalogs
node scripts/i18n.mjs check     # every message translated, same {placeholders} and <tags>
```

Unit tests run in French (`setDefaultLang('fr')` on the server, French by default on the web) and the
end-to-end tests use a French browser, so the French source text keeps being tested.
